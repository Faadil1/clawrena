# P3 — Judge Assurance & Real Failure Bundle

Canonical cycle:

`RUBRIC → PAIN → PROBLEM → DIFFERENTIATOR → EXECUTION → EVIDENCE → STORY → DEMO → Q&A`

No stage is considered complete merely because code exists. Each stage must hand a verifiable artifact to the next one.

## Invariants

1. **Real failure > fake success.**
2. `UNKNOWN != PASS`.
3. `PREPARE != EXECUTE`.
4. `PAPER != ONCHAIN`.
5. A signature is not enough by itself: confirmation must be independently checked before verified-volume accounting.
6. Historical incidents justify requirements; they are never presented as Alpha Scout results.
7. Test fixtures are labelled fixtures and cannot be used as submission evidence.
8. Failed provider preflight and stale evidence must create visible refusal evidence.
